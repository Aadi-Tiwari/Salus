Tier 01

The instant passive scan

Paste a URL. Salus reads the JavaScript bundle, the response headers and your app’s own public replies, looking for leaked keys, shipped source maps, missing security headers and dangerous backend defaults. Reading public bytes needs no authorization, so there is nothing to ask you for.

Open to anyone · 10s
Tier 02

The authorized deep test

Prove you own the domain, then hand over two test accounts. Salus signs in as both, crawls as account A to map the objects it references, then replays those exact requests as account B. When B receives A’s private record instead of an error, you are looking at a broken access control that Salus demonstrated rather than inferred.

Tier 03

The fix, and the re-test

An agent patches the missing check. Two tests then run instead of one: the original attack has to fail, and account A has to keep its own access. Salus marks the fix done only when both pass. If the agent stalls, Salus closes the tier and your proven Tier 2 finding still stands.

The accuracy problem

“How do you know that is a leak and not sharing?”

Anyone serious asks this first, so the answer is deterministic and written down. No model decides it. Salus calls a cross-account read a leak only when all three conditions hold at once.

01

B never saw it legitimately

The object never appeared in account B’s own authenticated session. A document you shared on purpose fails this test, because sharing already put it in B’s session.

02

Salus reached it by mutating an identifier

Changing an id in a URL or a request body was the only way in. If your app handed the object over through a normal link, that is not an attack.

03

The response is shaped like personal data

The body carries fields matching personal-information patterns: emails, addresses, card fragments, phone numbers. A public profile fails here, because public is the point of it.

if (!seen_by_B && reached_by_mutation && pii_shaped)
  → report as leak
else
  → never shown to you
The anti-gaming rule

The agent’s word is worth nothing.

Salus throws away the agent’s claim and runs two independent re-tests instead.

Regression guard

Test one: the attack must fail. The identical request that returned account A’s record a moment ago has to come back 403.

Test two: your app must still work. Account A has to read its own order and get 200 back, with the right data in it.

Both, or it is not done. If one test out of two passes, Salus rolls the patch back and leaves the finding open. You get no partial credit.

Fair questions

Before you scan.

Is it legal to run this?

On your own app, yes, and the whole product is built around that. Tier 1 reads only what a browser already downloads when it visits your page, so there is no authorization to exceed. Tiers 2 and 3 make you prove you own the domain by placing a token on it, and they run with test accounts you create. Salus refuses an authorized test against a domain you have not verified. You point it at your own product; it will not scan a stranger’s.

How do you avoid calling normal sharing a leak?

A deterministic rule handles it, not a model. Three conditions have to hold at once: account B’s own session never referenced the object, Salus reached the object only by mutating an identifier, and the response body carries personal-information-shaped fields. A document you shared fails the first condition. A public profile fails the third. Salus drops anything that misses a condition before you ever see it.

Will the fix break my app?

The second re-test exists to catch that. After a patch, Salus runs the attack again and it has to fail, then runs account A’s legitimate request and it has to succeed. If either check misses, Salus rolls the patch back and leaves the finding open. Fixes reach you as a pull request against your repository, so nothing lands until you merge it.

What if I did not use an AI builder?

The scan still runs and the cross-account replay still works, because broken access control belongs to no particular generator. You lose the fingerprint step, which trades a generic checklist for the specific list of things your builder gets wrong.

What happens to the data you pull out?

Salus redacts personal-information fields at capture and keeps only their shape, so a finding can prove an email address came back without storing the email address. You read the raw capture once, in your own session, and Salus discards it when you close the finding.

Why the ownership gate is the product

Scanning is ethical and legal when the person running it owns what gets scanned. Salus puts you, the owner, at the keyboard by design, and enforces it with a verification gate instead of a checkbox.

  • → Tier 1 reads public bytes only, so no authorization exists to exceed
  • → Tier 2 needs a token on your DNS or your web root
  • → You create the test accounts; Salus never harvests them
  • → Salus logs each authorized run against the account that authorized it
  • → Salus runs nothing against a domain you have not verified
