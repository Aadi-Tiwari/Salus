Product guide

Start locally. Verify every change.

Start a workspace

Install Node.js 22.17 or newer, clone Salus, and run npm start from the repository. Open http://127.0.0.1:8787. The scanner has no package dependencies or account requirement. A plain static web server can show these pages but cannot run scans or agents.

Start your target development app in a separate terminal, open the scanner, enter its local HTTP address, and select your checks. Confirm that you own or may test it.

Scope and responsible use

Only inspect applications you own or are explicitly authorized to test. Salus accepts loopback targets and unauthenticated GET requests. It reads the selected page and up to six same-origin scripts, with at most 24 requests and a 2 MB limit per resource.

Checks cover credential patterns, linked source maps, response headers, and framework signatures. External resources, failed downloads, encoded script URLs, inline source maps, and resource limits can leave coverage incomplete. Salus does not crawl routes, execute page JavaScript, test credentials, authenticate as users, or prove that access controls are correct.

Clean means no matching issue in the inspected scope. Found means evidence was observed. Partial or blocked means the check could not fully inspect its scope. None is a security certification.

Use a real agent

Install Codex CLI separately and run codex login. Salus checks that the executable is available and signed in. If discovery fails, set SALUS_CODEX_BIN to the native executable path before starting Salus. Git must also be available to validate patches.

In the console, attach relevant text source files. Set each path relative to the project root, such as src/server.js. Attach at most 20 files totaling 256 KiB. Credential files and known secret patterns are rejected, but inspect your files yourself too.

Choose a finished scan, evidence-backed findings, and a source snapshot. Consent to sharing that material, then run the agent. Salus invokes Codex with user configuration and agent instructions excluded, tool features disabled, a read-only sandbox, and a bounded structured response. Model output can only replace attached source paths. It never runs generated commands or applies changes to your original app.

Runs show actual runtime events and failures. A draft is downloadable only after git apply --check succeeds against the attached snapshot. Missing credentials, unavailable models, and failed runs stay visible as errors. There is no canned agent fallback.

Review, apply, and rescan

Read the complete patch and manual steps. Check the saved source hashes against your current files. From the target repository, run git apply --check path/to/salus.patch, then apply it only if you approve the changes.

Run the target application's relevant tests and restart its development server. Start a new scan using the same URL and checks. Compare the reports on the reports page. A finding disappearing in one check does not establish that the whole application is secure.

Privacy and local storage

Scans, source snapshots, and agent runs are saved under the ignored .salus/reports/ folder. Keep this folder private. Report URLs redact query values; findings redact known credential patterns. Source snapshots contain the selected full text, and draft patches can contain source code.

The scanner does not send reports to a model. When you explicitly start an agent, selected source and redacted evidence go through your configured Codex account for inference. Provider terms and usage limits apply. The interface loads fonts from public font providers. Salus binds to loopback and is intended for one trusted local user, not public multi-user hosting.

To remove saved data, stop Salus and delete its .salus folder. Downloaded patches are separate files that you manage yourself.
